## Specification
Dans `crates/puce-m68k-machines/src/ssc.rs`: `pub struct State { pub d: [u32; 8], pub a: [u32; 7], pub usp: u32, pub ssp: u32, pub sr: u32, pub pc: u32, pub prefetch: [u32; 2], pub ram: Vec<(u32, u16)> }`,
`pub enum Kind { Idle, Write, Read, Tas, ReadAddrErr, WriteAddrErr }`, `pub struct Trans { pub kind: Kind, pub cycles: u32, pub fc: u32, pub addr: u32, pub data: u32, pub uds: u32, pub lds: u32 }` (champs fc..lds a 0 pour Idle),
`pub struct Test { pub name: String, pub initial: State, pub final_: State, pub trans: Vec<Trans>, pub length: u32 }`,
`pub fn parse_file(bytes: &[u8]) -> Result<Vec<Test>, String>` (erreur claire si magic faux ou fichier tronque; jamais de panic).
Ecris aussi dans le module de test un encodeur minimal d'un fichier a 1 test pour tester le lecteur sans fichier reel.
Les deux points UNKNOWN de la spec (addr_bus octet/mot, cycles minimal) sont leves ICI: lis les 5 premiers tests de `tests/singlestep/NOP.json.bin` et `MOVE.w.json.bin`, ajoute la reponse (avec 2 exemples chiffres) dans `docs/specs/33_SINGLESTEP_FORMAT.md` section 4 (remplace les lignes UNKNOWN).

## 2. Un test

```
u32 numbytes, u32 magic = 0xABC12367
nom:      u32 numbytes, u32 magic = 0x89ABCDEF, u32 strlen, strlen octets UTF-8
etat initial   (voir 3)
etat final     (voir 3)
transactions   (voir 4)
```
Le lecteur parcourt sequentiellement et ignore `numbytes` (UNKNOWN - to confirm: si `numbytes` inclut ou non l'en-tete de 8 octets; sans importance tant qu'on lit champ par champ).
<!-- end -->

<!-- begin docs/specs/33_SINGLESTEP_FORMAT.md#3. Etat -->
## 3. Etat

```
u32 numbytes, u32 magic = 0x01234567
19 x u32 dans l'ordre: d0..d7, a0..a6, usp, ssp, sr, pc
u32 prefetch0, u32 prefetch1        (file de prefetch: IR puis IRC)
u32 num_rams
num_rams x { u32 addr (pair, < 0x1000000), u16 data }    mot de 16 bits a l'adresse addr (octet haut a addr, bas a addr+1)
```
- `pc` = valeur de `m_au` de MAME = **adresse du prochain mot a prefetcher** = adresse de l'instruction + 4 (l'instruction et son premier mot d'extension sont deja dans la file `prefetch0`, `prefetch1`).
- Seule la memoire touchee par le test est listee; le reste est ignore (le lecteur doit fournir une RAM dont le contenu hors liste est sans effet sur le resultat).
- `a7` n'existe pas dans l'ordre: A7 est `usp` ou `ssp` selon le bit S de `sr`.
<!-- end -->

<!-- begin docs/specs/33_SINGLESTEP_FORMAT.md#4. Transactions -->
## 4. Transactions

```
u32 numbytes, u32 magic = 0x456789AB
u32 num_cycles            (= duree totale en horloges, champ `length` du test)
u32 num_transactions
num_transactions x:
    u8  kind, u32 cycles
    si kind != 0: u32 fc, u32 addr_bus, u32 data_bus, u32 uds, u32 lds
```

| kind | Nom | Sens |
|---|---|---|
| 0 | `n` | cycle interne de `cycles` horloges (pas d'autres champs) |
| 1 | `w` | ecriture |
| 2 | `r` | lecture |
| 3 | `t` | cycle TAS (RMW) |
| 4 | `re` | lecture avec address error (AS non asserte, resultat non committe) |
| 5 | `we` | ecriture avec address error |

- `data_bus` suit le bus reel: octet par UDS seul -> 0xAB00 (voir 11_PINS_AND_TICK.md).
- Taille `.w`/`.b` deduite de `uds + lds` (2 = mot).
- UNKNOWN - to confirm (a lever dans E03-01 en lisant les premiers tests): `addr_bus` est-il une adresse d'octet ou de mot (A1..A23)? `cycles` d'une transaction de bus est-il toujours >= 4?
<!-- end -->

## Tests
Tous les tests sont prefixes par `e03_01_`.

- `e03_01_roundtrip` : fichier synthetique a 1 test: tous les champs relus a l'identique
- `e03_01_bad_magic` : magic de fichier faux -> Err
- `e03_01_truncated` : fichier tronque -> Err, pas de panic
- `e03_01_kinds` : les 6 valeurs de `kind` (0..5) sont decodees; 6 -> Err
- `e03_01_ram_words` : une entree RAM (addr pair, mot) est conservee telle quelle
- `e03_01_real_nop` : si `tests/singlestep/NOP.json.bin` existe: 2500 tests, chacun avec `length` > 0 (sinon le test passe sans rien verifier)
