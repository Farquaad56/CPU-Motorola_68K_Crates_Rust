# E03-05 - Runner: execution et comparaison d'un test
Epopee: E03 | Type: code | Dependances: E03-04 | Taille estimee: ~150 lignes

## Contexte
Execute un test SingleStepTests: charge l'etat, joue `length` horloges, compare etat final et transactions.

## Specification
Dans `ssc.rs`: `pub enum Outcome { Pass, SkipAddrError, Fail(String) }`, `pub fn run_test(cpu: &mut Cpu, ram: &mut FlatRam, t: &Test) -> Outcome`.
1. Si une transaction du test est `ReadAddrErr`/`WriteAddrErr` -> `SkipAddrError` (D-030) sans rien executer.
2. `ram.clear_touched()`, ecrit `initial.ram` (mots), `cpu.load_state(...)` (sr, pc, prefetch...), vide le journal, `cpu.step_clocks(&mut ram, t.length)`.
3. Compare: registres et SR de `final_`, file de prefetch, memoire (chaque mot de `final_.ram`), puis journal vs `t.trans` (kind, cycles, fc, addr, data, uds, lds; octet seul -> donnee sur le bus comme dans la spec 33).
4. `Fail(msg)`: le message nomme le test, le premier ecart (champ, attendu, obtenu) et le numero de transaction.

## 5. Comparaison attendue (E03-03)

Apres execution de `num_cycles` horloges depuis l'etat initial: tous les registres de l'etat final, la file de prefetch, la memoire listee dans l'etat final, et la liste des transactions (kind, cycles, fc, addr, data, uds, lds) doivent etre identiques.

## Regles de lecture des resultats SingleStepTests

- Les tests sont generes depuis le coeur microcode de **MAME**, pas depuis du materiel: un bug MAME se retrouve dans les tests (D-007).
- Tests contenant un cycle `re` ou `we` (address error): ignores jusqu'a l'epopee E11 (comptes a part: `skipped_addr_error`).
- Exceptions connues (liste dans `docs/specs/data/sst_known_exceptions.txt`, une ligne `stem<TAB>raison`): TAS (timing RMW), TRAPV (comportement du bit S). Un fichier liste = les echecs de ce stem ne font pas echouer `--strict`.
- Pas de ROM de timing verifiee sur materiel connue publiquement (Nemesis n'a jamais publie la sienne). Cas douteux: recouper avec FX68K (https://github.com/ijor/fx68k) a la main, puis noter la decision dans DECISIONS.md.
<!-- end -->

## Tests
Tous les tests sont prefixes par `e03_05_`.

- `e03_05_skip_addr_error` : un test avec un cycle `re` donne SkipAddrError
- `e03_05_fail_reg` : un test dont d0 final est faux donne Fail avec le nom du registre
- `e03_05_fail_cycles` : une transaction de duree differente donne Fail avec l'indice
- `e03_05_pass_synthetic` : un test synthetique construit pour NOP et un coeur factice passe
- `e03_05_msg_names_test` : le message contient le nom du test
